# Task 20. Irregular graph workloads

Gustafson needs approximately constant useful work per rank and bounded exposed overhead. Equal vertex counts in a power-law graph do not imply equal edge counts. A few high-degree vertices can dominate adjacency scans, outgoing messages and atomic updates. Random memory access causes cache misses and poor prefetching, while remote accesses expose network latency. Increasing graph capacity does not supply proportional memory bandwidth or balanced work.

BFS is especially sensitive to its changing frontier: early and late levels expose little parallel work, middle levels flood the network, and each level may require a global termination test. Growing graph diameter adds synchronization rounds. PageRank has a more regular iteration schedule but still exchanges rank contributions along irregular edges; high-degree partitions and all-rank reductions can dominate. Fixed convergence tolerance can change iteration counts as graph structure changes, so edges/second alone need not imply fixed solution time.

Dense linear algebra benefits from block locality, predictable work and reusable tiles. Graph processing has much lower and less predictable work per transferred byte. Partition by edges as well as vertices, use direction-optimizing BFS, compressed adjacency, aggregated messages and local combining where suitable. These interventions must be benchmarked on a defined graph family with fixed degree distribution, accuracy and stopping rule. Record maximum rank time, communication volume and iteration counts; average local work alone does not validate a fixed alpha.
